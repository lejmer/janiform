## Initiative 012: Repository Documentation Professionalization

Bring Janiform's full repository documentation surface to a professional standard suitable for internal engineering work, external open-source adoption, and financial-community due diligence. This initiative treats all tracked Markdown as part of a governed documentation portfolio, including root docs, published docs, crate READMEs, fixture READMEs, contributor guidance, design records, and planning material.

### Desired outcome
- Janiform has a documentation system with clear audience boundaries, canonical sources, and professional first-contact pages.
- Users can move from installation to successful market-data calibration, simulation, pricing, and interpretation without being forced through internal design notes or planning artifacts.
- Contributors can tell where new documentation belongs, how it is reviewed, and how it is kept aligned with the product.
- The repository has quality gates and ownership rules that keep docs from drifting back into ad hoc sprawl.

### Success signals
- Every tracked `.md` file has an explicit role and disposition.
- Public, contributor, internal-design, planning, generated, and archive surfaces are clearly separated.
- The root trust surface is concise, accurate, and suitable for external review.
- Public docs are executable, linked, current, and organized around user tasks rather than repository history.
- Local READMEs and generated Markdown follow role-appropriate templates and source-of-truth rules.
- Documentation standards, review checklists, and release gates are documented and used.
