## Canonical Mean Reversion Contracts And Persistence

### Description
Introduce the canonical domain contracts and persisted artifact shapes required for the anchor-deviation mean-reversion layer.

This issue must not change seeded runtime, coarse runtime, pricing behavior, or calibration logic yet. Its job is to define the new model and runtime payloads so later issues can consume them without inventing their own local representations.

The new layer is:

```latex
\[
X_t = A_t + D_t,
\qquad
dD_t = -\kappa D_t\,dt + dX_t^{\mathrm{JF}} - dA_t.
\]
```

For executable interval-grid workflows, later runtimes will use the canonical piecewise-constant anchor rule:

```latex
\[
X_{h+1} = a_{h+1} + e^{-\kappa \Delta_h}(X_h - a_h) + R_h,
\]
```

where:
- `a_h` is the anchor value held fixed on interval `h`
- `R_h` is the Janiform core contribution generated by the chosen runtime for that interval

This issue must define the contract objects needed to represent:
- whether mean reversion is enabled
- the fitted parameter block
- the anchor specification used by persisted fitted models
- the runtime-aligned anchor values used by seeded and coarse execution
- the observed-state boundary data carried between intervals

### Required contract additions
- Add a canonical Rust domain type for fitted mean-reversion parameters.
- Add the matching Python contract type.
- Add persisted calibration artifact support for the new parameter block.
- Add a runtime-aligned interval-anchor payload shared by seeded and coarse workflows.
- Add a boundary-state payload for the observed layer.

The contract split must be explicit:

1. Fitted model parameters
    - `kappa`
    - anchor model specification

2. Runtime materialization output
    - interval-aligned start anchor
    - interval-aligned end anchor by interval
    - interval length alignment metadata

3. Boundary state
    - observed log-price `X_h`
    - anchor value `a_h`
    - deviation `D_h`

The boundary-state contract must validate the invariant

```latex
\[
D_h = X_h - a_h.
\]
```

### Anchor model scope
The canonical fitted-parameter contract must support the following anchor model families:
- disabled
- constant anchor
- deterministic interval-grid anchor

`deterministic interval-grid anchor` means the fitted model can persist a low-dimensional anchor source that later materializes to one aligned anchor value per runtime interval. It does not mean seeded or coarse runtimes should infer anchors implicitly from timestamps at this stage.
